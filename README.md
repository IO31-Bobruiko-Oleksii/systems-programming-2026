# Геліостат — прошивка, стенд і тести (ЛР1–ЛР2)
 
Прошивка для STM32 NUCLEO-C031C6 (STM32C031C6) системи стеження за Сонцем: чотири датчики освітленості (у симуляції — потенціометри), два сервоприводи, носій для журналу (у симуляції — мікро-SD) і консоль на USART2. Стенд працює у симуляторі Wokwi; проєкт зібрано в Docker, логіку покрито хостовими тестами, а шини перевірено записами логічного аналізатора.
 
## Структура
 
```
firmware/            прошивка
  Core/              код, згенерований CubeMX (main.c, msp, переривання)
  Drivers/           HAL і CMSIS від ST (без змін)
  platform/inc,src   платформний інтерфейс (plat_*.h) і його реалізація над HAL (plat_*_hal.c)
  devices/           драйвери пристроїв: servo, pots, sdcard
  app/               самоперевірка й консоль
  build.mk           підключає шари до Makefile, згенерованого CubeMX
  firmware.ioc       проєкт CubeMX
tests/               хостові тести, підробки шин (fakes/), вектори з записів (vectors/)
scripts/             перевірка залежностей, запис і декодування VCD, перевірка формату самоперевірки
scenarios/           сценарії Wokwi для записів логічного аналізатора
docs/                документація (див. нижче) і звіти
docker/Dockerfile    образ зі збірним інструментарієм
diagram.json         схема стенда у Wokwi
wokwi.toml           конфігурація запуску Wokwi
.github/workflows/   CI (GitHub Actions)
```
 
## Вимоги
 
- Docker і `make` — збірка прошивки (`make build`).
- `wokwi-cli` і токен у змінній середовища `WOKWI_CLI_TOKEN` — запуск симуляції (`make flash`, `make capture`). Токен у репозиторії не зберігається.
- `cc` (gcc) і `gcov` — хостові тести й покриття.
- `python3` — розбір VCD; `sigrok-cli` — додаткові декодери (необов'язково); PulseView — перегляд записів.
## Команди
 
| Команда | Дія |
|---|---|
| `make build` | збірка прошивки в контейнері (`-Wall -Wextra -Werror` для власного коду) |
| `make flash` | симуляція у Wokwi; успіх — рядок `SELFTEST END total=5 passed=5 failed=0` протягом 15 с |
| `make monitor` | симуляція без обмеження за часом, вивід консолі |
| `make test` | хостові тести (76 тестів, 343 перевірки) |
| `make check-deps` | перевірка правил залежностей між шарами |
| `make check` | `check-deps` і `test` |
| `make coverage` | покриття рядків драйверів і застосунку (gcov), поріг 90 %; зараз 97,78 % |
| `make capture NAME=boot` | запис логічного аналізатора за сценарієм `scenarios/boot.yaml` у `docs/captures/boot.vcd`; `NAME=all` — усі шість |
| `make clean` | видалення `firmware/build` |
 
Сценарії записів: `boot`, `console`, `adc`, `servo`, `sdread`, `nosd`. Текстові розшифровки створює `scripts/decode_captures.sh`.
 
## Підключення
 
| Пристрій | Виводи | Інтерфейс |
|---|---|---|
| Потенціометри (датчики освітленості) | `PA0`, `PA1`, `PB1`, `PB2` | АЦП1, канали `IN0`, `IN1`, `IN18`, `IN19` |
| Сервоприводи | `PC6`, `PC7` | ШІМ, `TIM3_CH1`, `TIM3_CH2`, період 20 мс |
| Мікро-SD | `PA5` (SCK), `PA6` (MISO), `PA7` (MOSI), `PB9` (CS) | SPI1, режим 0, програмний CS |
| Консоль і самоперевірка | `PA2` (TX), `PA3` (RX) | USART2, 115200 8N1 |
| Маркер вимірювання АЦП (службовий) | `PB3` | канал D7 логічного аналізатора |
 
Повна таблиця з обґрунтуванням, бюджет живлення й відкриті питання — у [docs/pinout.md](docs/pinout.md).
 
## Консоль
 
Після скидання прошивка друкує банер і звіт самоперевірки (формат — [docs/selftest-format.md](docs/selftest-format.md)). Команди консолі: `help`, `selftest`, `adc`, `servo <1|2> <кут>`, `sd init`, `sd read <блок>`.
 
## Архітектура
 
Шари: `app` → `devices` → інтерфейс платформи (`plat_*.h`) ← адаптери над HAL. Драйвери й застосунок не підключають заголовків HAL; правило перевіряє `scripts/check_deps.sh` (команда `make check-deps`, у CI входить до `make check`). Інтерфейс платформи прив'язується на етапі компонування: на платі — адаптери над HAL, на хості — підробки з `tests/fakes/`. Діаграма компонентів, таблиця модулів HAL і версії інструментів — у [docs/architecture.md](docs/architecture.md).
 
## Тести і покриття
 
Хостові тести (`tests/`) збираються звичайним `cc` без плати й без симулятора. Драйвер SD додатково перевірено на байтах, записаних логічним аналізатором (`tests/vectors/`, `test_sd_replay`). Покриття — 97,78 % рядків (397 із 406) при порозі 90 %; код адаптерів над HAL і `Core/` у покриття не входить. Деталі — у розділі 8 звіту ЛР2.
 
## CI
 
GitHub Actions виконує на кожен `push` і `pull_request` два завдання: `make check` із `make coverage` (хостові тести, перевірка шарів, поріг покриття) і `make build` у Docker-образі з перевіркою відсутності попереджень компілятора.

## Відомі обмеження
 
- Після скидання лінія `PB9` (CS) лишається низькою до `plat_spi_init()` (близько 3,85 мс), бо `MX_GPIO_Init()` від CubeMX пише на неї низький рівень. Усунення («GPIO output level: High») свідомо не застосовано, щоб числа аналізу відповідали записам; дефект описано в `docs/captures/analysis.md`.
- Симулятор не моделює перемички плати, кварц `PC14`/`PC15`, струми, ємність вибірки АЦП і якість фронтів. Що саме треба перевірити на обладнанні — у розділах 3.6 і 6.8 звіту ЛР2.
- Образ збірки позначено тегом `ubuntu:22.04`, пакети apt не закріплено; версії зафіксовано лише в документації.
